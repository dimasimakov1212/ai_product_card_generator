# AI-помощник для подготовки товарных описаний

REST API-сервис на FastAPI, который генерирует структурированные черновики карточек товаров для B2B-интернет-магазина на основе входных технических данных с использованием LLM.

## Быстрый старт

```bash
# 1. Клонировать и перейти в папку
git clone <repo_url> && cd ai_product_card_generator

# 2. Создать виртуальное окружение
python -m venv venv
source venv/bin/activate

# 3. Установить зависимости
pip install -r requirements.txt

# 4. Настроить переменные окружения
cp .env.example .env
# - Добавьте OPENAI_API_KEY
# - Если вы находитесь в регионе с ограничениями, укажите OPENAI_BASE_URL (например, https://routerai.ru/api/v1)

# 5. Запустить сервис
uvicorn app.main:app --reload
```

Сервис будет доступен по адресу: **<http://127.0.0.1:8000>**

- Swagger UI: <http://127.0.0.1:8000/docs>
- ReDoc: <http://127.0.0.1:8000/redoc>

> 💡 Если API-ключ не указан, сервис автоматически перейдет в **демо-режим** и вернет мок-ответ, демонстрирующий корректную обработку неполных данных.

## API Endpoints

### `GET /health`

Проверка работоспособности сервиса.

### `POST /generate`

Генерация карточки товара.

**Request body (JSON):**

```json
{
  "name": "МК110-224.8Д.4Р [М01]",
  "manufacturer": "ОВЕН",
  "specs": {
    "Интерфейс": "RS-485",
    "Протоколы": "Modbus RTU"
  },
  "description": "Модуль для сбора данных и управления..."
}
```

**Пример вызова через curl:**

```bash
curl -X POST http://127.0.0.1:8000/generate \
  -H "Content-Type: application/json" \
  -d @data/product1_full.json
```

**Response (200 OK):**

```json
{
  "seo_title": "Модуль ввода-вывода ОВЕН МК110-224.8Д.4Р, RS-485",
  "seo_description": "...",
  "key_specs": ["Интерфейс: RS-485", "Протоколы: Modbus RTU"],
  "search_queries": ["ОВЕН МК110-224.8Д.4Р купить"],
  "commercial_block": "...",
  "missing_data_warning": "Нет"
}
```

## Промпт и принятые решения

1. **Strict JSON через Pydantic + `response_format`:** Используется `client.beta.chat.completions.parse` с Pydantic-схемой. Это гарантирует, что LLM вернет именно ту структуру, которую ожидает FastAPI (и автоматически валидируется через `response_model`).
2. **Борьба с галлюцинациями:** В промпте жестко прописано правило: если данных нет — писать "данных нет", а не выдумывать. Это подкреплено нормализацией входа в `services.py`.
3. **Явная обработка неполных данных:** Если во входном JSON поле пустое или отсутствует, оно заменяется на "данных нет" **до** отправки в LLM. Это вынуждает модель корректно заполнить `missing_data_warning`.
4. **Идиоматичный FastAPI:**
   - `Depends(get_settings)` для DI конфигурации
   - `lifespan` для корректного управления жизненным циклом
   - `HTTPException` с адекватными кодами (400, 502)
   - Автоматическая OpenAPI-документация
5. **Безопасность:** API-ключ загружается через `pydantic-settings` из `.env`, который добавлен в `.gitignore`.

## Ограничения и возможные улучшения

**Текущие ограничения (MVP):**

- Один провайдер LLM (OpenAI).
- Нет аутентификации API (rate limiting, API keys для клиентов).
- Нет персистентного хранения истории запросов.

**Возможные улучшения (Next Steps):**

1. **Мульти-модельность:** Интеграция `LiteLLM` для переключения между OpenAI/Anthropic/YandexGPT через одну переменную окружения.
2. **Автоматическое обогащение:** При наличии поля `url` во входном JSON — автоматический парсинг сайта производителя перед отправкой в LLM.
3. **Пост-валидация длины:** Python-обертка, которая проверяет, что `seo_title` ≤ 70 символов, а `seo_description` в диапазоне 800–1200, и при нарушении делает повторный запрос к LLM на корректировку.
4. **Кэширование:** Redis-кэш для одинаковых входных данных, чтобы экономить токены.
5. **Асинхронность:** Переход на `AsyncOpenAI` и `async def` эндпоинты для высокой нагрузки.
6. **Тесты:** Покрытие `pytest` + `httpx` для проверки всех edge-cases (неполные данные, ошибки API, невалидный JSON).
